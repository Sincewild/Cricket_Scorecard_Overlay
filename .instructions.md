# Cricket Scorecard Overlay - Development Instructions

## Project Overview

**Cricket Live Overlay for YOLOBox Ultra** is a self-hosted Node.js service that scrapes live cricket scores from CricClubs and serves them as:
1. An HTML overlay for broadcasting (YOLOBox, browser sources)
2. A JSON API for programmatic access

## Tech Stack

- **Runtime:** Node.js 18+
- **Framework:** Express.js
- **Browser Automation:** Playwright (for scraping)
- **Security:** Helmet, CORS, Rate Limiting
- **Dependencies:** cors, express-rate-limit, helmet, cloakbrowser, playwright-core

## Project Structure

```
src/
  ├── app.js                    # Express app, middleware, route handlers
  ├── config.js                 # Environment-driven configuration
  ├── index.js                  # Process entrypoint, graceful shutdown
  ├── state.js                  # Initial score data model
  ├── logos/                    # Team logo images
  ├── scraper/
  │   ├── cricclubsScraper.js  # Playwright browser automation & DOM scraping
  │   └── parseScore.js         # Heuristic score text parser
  ├── services/
  │   └── scoreService.js       # Polling scheduler & in-memory cache
  └── utils/
      ├── validateMatchUrl.js   # URL validation & allowlist logic
      └── teamLogoResolver.js   # Team logo path resolution
public/
  ├── admin.html                # Admin/control panel UI
  ├── overlay.html              # YOLOBox overlay UI (polled by frontend)
```

## Data Flow

```
CricClubs website
    ↓ (Playwright scraper, every 20-45s)
In-memory cache (scoreService)
    ↓ (HTTP polling)
/score JSON endpoint
    ↓
overlay.html (client-side polling)
    ↓
YOLOBox Web URL source
```

## Key Configuration

All via environment variables (see `config.js`):

- **PORT** (default: 3000) - HTTP server port
- **NORMAL_INTERVAL_MS** (default: 20000) - Polling interval during match
- **POST_OVER_INTERVAL_MS** (default: 45000) - Polling interval after over ends
- **MATCH_URL** (optional) - Pre-configured match URL

## API Endpoints

- `GET /` - Serves overlay.html
- `GET /admin` - Serves admin.html
- `POST /set-match` - Set new match URL (rate-limited)
- `GET /score` - Returns current score as JSON
- `GET /health` - Health check endpoint

## Development Patterns

### 1. URL Validation
- **All match URLs must be validated** before scraping
- See `src/utils/validateMatchUrl.js`
- Pattern: validate first, then fetch

```javascript
const { validateMatchUrl } = require('./utils/validateMatchUrl');
if (!validateMatchUrl(url)) {
  return res.status(400).json({ error: 'Invalid match URL' });
}
```

### 2. Score Parsing
- Located in `src/scraper/parseScore.js`
- Uses heuristics to extract score data from DOM text
- Returns score object with: runs, wickets, overs, batsmen, bowlers, etc.

### 3. Error Handling
- All scraper operations must handle network failures gracefully
- Use try-catch in async operations
- Log errors but don't crash the server
- Cache stale data if scraper fails

### 4. Team Logos
- Store PNG/SVG files in `src/logos/`
- Use `teamLogoResolver.js` to resolve team name → logo path
- Keep file names lowercase, no spaces: `team-name.png`

### 5. State Management
- Score state is immutable, stored in memory
- See `src/state.js` for initial model
- Updates via `scoreService.updateScore()`

## Code Conventions

- **Naming:** camelCase for variables, functions; PascalCase for classes
- **Async patterns:** Use async/await, avoid callbacks
- **Errors:** Always validate before processing (fail-fast)
- **Logging:** Simple console.log for now; structured for production
- **Comments:** Explain "why", not "what"; code should be self-documenting

## Common Tasks

### Adding a New Cricket Source
1. Create new scraper in `src/scraper/newSourceScraper.js`
2. Export same interface as `cricclubsScraper.js`: `{ scrapeScore(url, browser) }`
3. Add to `src/services/scoreService.js` scraper selection logic
4. Update URL validation in `src/utils/validateMatchUrl.js` if needed

### Fixing Score Parsing Issues
1. Check `src/scraper/parseScore.js` - where the heuristic parsing happens
2. Print the raw DOM text to debug: `console.log(text)`
3. Adjust regex patterns or parsing logic to handle edge cases
4. Test with real CricClubs scorecard

### Adding Team Logos
1. Place PNG/SVG in `src/logos/` with name: `team-name.png`
2. Update team name mapping in `src/utils/teamLogoResolver.js`
3. Logos are served via `GET /logo/:teamName`

### Debugging the Scraper
1. Enable debug mode: `DEBUG=cloakbrowser node src/index.js`
2. Check network failures in `scoreService.js` - verify Chromium sandbox args
3. Test URL with manual Playwright script first

## Security Considerations

- **Rate limiting:** `/set-match` limited to 20 req/min per IP
- **URL validation:** All user-provided URLs validated before scraping
- **Sandbox:** Playwright runs Chromium in sandboxed mode (`--no-sandbox` only for containers)
- **CORS:** Enabled for all origins (intentional for browser embedding)
- **CSP:** Disabled (overlay must load external resources)

## Deployment Notes

- Designed for Render.com (see `render.yaml`)
- Requires Chromium runtime: check buildpack includes `heroku/buildpacks:apt`
- Graceful shutdown on SIGTERM (configured in `index.js`)
- Stateless except for in-memory cache (restart = reset score)

## Performance Considerations

- Polling intervals vary by game state (20s during play, 45s after overs)
- Browser automation is single-threaded; only one match at a time
- Cache prevents redundant scrapes within interval
- Rate limiting protects `/set-match` endpoint from abuse

## Testing & Validation

- `npm run check` - Syntax validation with `node --check`
- Manual testing: `npm start` then visit http://localhost:3000
- Overlay test: Load `http://localhost:3000` in YOLOBox

## Troubleshooting Guide

| Issue | Check |
|-------|-------|
| Blank overlay | Is `/score` returning valid JSON? Check browser console. |
| Scraper fails | Verify Chromium can run; check `config.js` sandbox args. |
| Match URL rejected | Validate with `validateMatchUrl.js` logic. |
| Stale scores | Check polling interval; verify scraper didn't error. |
| Port already in use | Change PORT env var or kill existing process. |
